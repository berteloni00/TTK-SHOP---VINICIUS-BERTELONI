Método: Inteligência de TikTok Shop via FastMoss

Documentação do processo completo usado para gerar as análises de TikTok Shop do Hub 4D (Análise de Beleza, Top 200 Marcas, Creators de Acessórios). Serve como runbook para reproduzir e para criar novas análises de nicho.

TL;DR do princípio-chave: os dados vêm do FastMoss (conta Flagship). O jeito que funciona é dirigir a interface real do FastMoss (Edge logado, em modo depuração) e capturar as respostas JSON assinadas que a própria página dispara. Nunca forjar fetch direto na API dos dados: dispara anti-bot (retorna dados demo falsos ou captcha).

1. Fonte de dados e acesso

  • Ferramenta: FastMoss (fastmoss.com), edição Flagship, conta logada no Microsoft Edge.
  • Por que não é uma API "limpa": o FastMoss assina cada request no front (params df, _time, cnonce + fingerprint). Sem essa assinatura, a API devolve:
  • MAG_AUTH_3011 / 3006 / 3002 (não autorizado) e/ou payload demo (nicks estrangeiros, moeda errada tipo RM/฿) que parece real mas é fixo;
  • MSG_SAFE_0001 = captcha anti-bot, que trava a sessão até ser resolvido na janela.
  • Regra de ouro: deixar a página do FastMoss fazer o request (clicando filtros, paginando) e só capturar a resposta. Ritmo humano (2 a 3 s entre ações) passa limpo.

1.1 Abrir o Edge em modo depuração (com o perfil logado)

Get-Process msedge -ErrorAction SilentlyContinue | Stop-Process -Force
Start-Process "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" `
  -ArgumentList '--remote-debugging-port=9222', `
  "--user-data-dir=$env:LOCALAPPDATA\Microsoft\Edge\User Data", `
  '--profile-directory=Default', 'https://www.fastmoss.com/pt/dashboard'
  • Sessão é de dispositivo único e volátil. Fechar o Edge, expirar, ou logar a mesma conta em outro lugar (celular, outra aba) derruba a sessão. Sinal: is_login=0 / MSG_30001. Solução: relogar na janela do Edge.
  • Conferir login (via fetch do próprio site, esse endpoint não é gated): GET /api/user/index/userInfo → ext.is_login === 1.

1.2 Automação: CDP cru, não puppeteer

O puppeteer trava (Network.enable timed out) ao anexar em páginas SPA pesadas do FastMoss, e crasha quando um clique abre nova aba. A automação usa CDP cru (WebSocket direto no DevTools Protocol), que é estável mesmo quando o puppeteer trava. Helper: cdp.js.

Capacidades do helper: navigate, evaluate (rodar JS na página), clickText, enableCapture(regex) (guarda respostas JSON de URLs que casam a regex) e drainCaptured().

2. Endpoints do FastMoss (mapa)

Todos em base https://www.fastmoss.com/api/. Capturados dirigindo a UI.

Endpoint O que traz Params-chave
shop/v3/shopList Ranking de lojas l1_cid (categoria), l2_cid (subnicho), date_type=3&date_value=YYYY-MM (mês fechado), order=1,2, page, pagesize=10
shop/V3/categoryInfo Árvore de categorias L1 + subnichos (c_code) —
shop/v3/author Creators de uma loja (GMV/loja) id=<seller_id>, d_type=28, order=2,2, pagesize
shop/v3/videoAnalysis Vídeos de uma loja gated no plano (retorna demo). Evitar.
goods/v3/video Vídeos de um produto com GMV, ROAS, gasto ads product_id, date_type=28, pagesize=5, is_promoted=-1
video/hotGoodsVideoGroupByProduct Top produtos por vendas + video_list (criativos) l1_cid, rank_type=28, region=BR
author/search Busca de influenciadores (ranking global de creators) sale_category_l1 (categoria de vendas), columnKey/field (ordenação), page
author/index/country, shop/V3/baseInfo, goods/v3/base metadados de apoio —

2.1 Página de detalhe da loja

/pt/shop-marketing/detail/<seller_id> — ao rolar a página, dispara sozinho o shop/v3/author (top 5 creators, 28d) com o GMV que cada creator gerou para aquela loja. É a fonte confiável de "creators por loja" (e de "por quais empresas um creator vendeu").

3. Pegadinhas importantes (aprendizados)

  1. O ranking de lojas é por UNIDADES vendidas, não por GMV. order=1,2 ordena por quantidade. Uma loja de eletrônico barato fica em 1º por volume, mas fatura menos que uma de ticket alto. Para "maiores por faturamento": colete tudo (até 500, o teto do ranking) e reordene por GMV do seu lado.
  2. Janela de tempo: o mês-calendário fechado (ex.: Junho) só existe no ranking de lojas (date_type=3&date_value). Creators e vídeos por loja só têm janela móvel (d_type=28 / 90). O FastMoss tem defasagem de ~2 dias (28d vai até ~anteontem).
  3. Vídeos por loja (videoAnalysis) é gated e devolve demo. Use goods/v3/video por produto (traz GMV, ROAS, estimate_cost_amount = gasto de ads).
  4. Gasto de ads é uma ESTIMATIVA (estimate_cost_amount); às vezes vem 0 (orgânico ou o FastMoss não estimou) → ROAS não calcula. Mostrar como "-".
  5. Duplicatas de vídeo: o mesmo vídeo aparece em vários produtos/lojas; só uma instância carrega o gasto real. Deduplicar por video_id mantendo a de maior gasto/ROAS.
  6. author/search (busca de influenciadores) só ordena por unidades vendidas 28d e os creators são generalistas (vendem 40+ categorias); o volume é o total deles, e não mostra por quais lojas. Para "por quais empresas" + volume específico do nicho, use o caminho loja → creators (shop/v3/author).
  7. Captcha por rajada: fetch in-page em série (>~30) dispara MSG_SAFE_0001. Pace em ~2,6 s ou dirija a UI (paginação por clique).
  8. Números do FastMoss vêm "tortos" para pt-BR: "R$4.7 milhão" (singular, ponto decimal). Normalizar: "R$ 4,7 milhões" (plural conforme valor, vírgula). Função br() nos builders.

4. Pipelines por tipo de análise

Cada análise = coleta (Node/CDP) → JSON → build (Python) → Excel + HTML → publica.

A) Análise de nicho (ex.: Beleza) — out_beleza/

  1. pull_categories.js / categoryInfo → subnichos (l2_cid).
  2. Fase 1 collect_beleza.js: por subnicho, dirige o ranking mensal e captura shopList (top 5 lojas, l1_cid + l2_cid + date_value=YYYY-MM).
  3. Fase 2: navega o detalhe de cada loja, captura shop/v3/author (top 5 creators, 28d), com o GMV por loja. Valida que o id= da resposta bate com a loja (evita "capture bleed").
  4. Criativos: collect_criativos.js (hotGoodsVideoGroupByProduct) + collect_criativos5.js (goods/v3/video por produto → GMV, ROAS, gasto, top 5 por produto).
  5. build_final.py → Analise_Nicho_Beleza.xlsx (4 abas) + .html.

B) Top N marcas (todas as categorias) — out_top100/

  1. collect_top100.js: ranking mensal sem filtro de categoria, pagina até 500 (o teto).
  2. build_top100.py: reordena por GMV, corta top 200 (piso de R$ 50 mil), gera HTML com filtro por categoria + busca, e selos (fitness, feminino) por regex de categoria.

C) Creators de um nicho + por quais empresas (ex.: Acessórios) — out_acessorios/

  1. collect_acessorios.js: Fase 1 top lojas de acessórios (shopList l1_cid=8, paginado); Fase 2 creators de cada loja (shop/v3/author, 28d).
  2. collect_influ_acessorios.js (opcional): author/search para enriquecer com o volume geral do creator.
  3. collect_acess_video_roas.js: produtos de acessórios + goods/v3/video (GMV, ROAS, gasto).
  4. build_acessorios.py: agrega por creator (soma GMV entre as lojas + divisão de GMV por empresa) e monta a seção de vídeos por performance (dedup por video_id).

5. Geração da saída (builders Python)

  • Excel via openpyxl (abas por tema, links do TikTok clicáveis).
  • HTML self-contained (roda offline / como Artifact), com:
  • Identidade Elevate: paleta navy/teal/coral, fonte Poppins, accent bar, fundo em gradiente, assinatura "Elevate Ecom". (Ver seção 6.)
  • Normalização pt-BR dos números (br()), acentuação correta.
  • Elementos: hero com KPIs, seções numeradas, tabelas com barras de GMV, divisão por empresa (chips + barra empilhada), selo AD/orgânico, link direto do TikTok (https://www.tiktok.com/@<unique_id>/video/<video_id>), nota de leitura do ROAS.

5.1 Link do vídeo no TikTok

Montado a partir de unique_id (handle) + video_id: https://www.tiktok.com/@{unique_id}/video/{video_id}.

7. Publicação no Hub 4D

O Hub 4D é o próprio repo desta pasta-raiz (CONTINGENCIA = repo github.com/fox-ttssquad/elevate-4d-hub), com auto-deploy no Vercel a cada push na main.

  1. Copiar o HTML/Excel para uma pasta versionada (não gitignored): Entregaveis/<Nome-Da-Analise>/index.html (+ .xlsx).
  2. Adicionar um card na seção Inteligência de Marketplaces do index.html (raiz). O Hub classifica o card por marketplace pelo link (função keysFor): o padrão da URL precisa casar com o regex de TikTok (ex.: TikTok, Analise-Nicho-Beleza, Creators-Acessorios), senão o card aparece em todos os filtros por engano.
  3. Commit cirúrgico (só os arquivos da entrega, nunca git add -A — há dados de cliente gitignored) e git push → deploy em ~1 min.

URL de produção: https://elevate-4d-hub-git-main-fox-squad-s-projects.vercel.app/ (sempre o alias fixo da main; nunca as URLs com hash, que são congeladas).

8. Runbook (reproduzir do zero)

# 1. Abrir Edge logado em modo depuração (PowerShell da seção 1.1) e logar no FastMoss.
# 2. Confirmar login (deve dar is_login=1):
node -e "require('./cdp')...userInfo"           # ou os scripts check de login

# 3. Coletar (exemplos):
node collect_top100.js 50                        # 500 marcas -> reordena por GMV no build
node collect_acessorios.js 8                     # lojas de acessorios -> creators
node collect_acess_video_roas.js 4 25            # videos de acessorios com ROAS

# 4. Gerar saida:
python build_top100.py
python build_acessorios.py

# 5. Publicar no Hub:
#   cp para Entregaveis/<Nome>/  ->  editar card no index.html  ->  git add (cirurgico) + push

Se aparecer captcha (MSG_SAFE_0001) ou is_login=0: resolver na janela do Edge / relogar, e rodar de novo (coletores são resumíveis, pulam o que já foi coletado).
