Banco Central das Análises 4D — Setup (Supabase)

Elevate Ecom (Metodologia Interna) · Como criar o banco que guarda cada análise da Entrada de Dados 4D, por cliente · Atualizado: 2026-06-16

A página Entrada de Dados 4D pode salvar cada análise num banco central (Supabase), marcada por cliente. Assim dá pra responder "qual empresa tem o quê" e comparar no tempo. Este guia cria esse banco. Faça uma vez.

Modelo de segurança (leia antes)

  • O banco é seu (projeto Supabase na sua conta). O dado confidencial fica sob seu controle — não na Vercel.
  • A página é pública e usa a chave anon (pública por design). O RLS garante que a página só INSERE — ler os dados exige login no painel do Supabase.
  • Nunca use a chave service_role na página/config (ela é secreta e dá acesso total).
  • A página pública pode, em tese, inserir linhas (write-only). Para uso interno, tudo bem; se virar problema, dá pra adicionar uma "chave da equipe" depois.

Passo 1 — Criar o projeto

  1. Acesse supabase.com → entre com a conta da Elevate → New project.
  2. Dê um nome (ex.: elevate-4d), defina uma senha de banco e a região (South America se disponível).

Passo 2 — Criar a tabela + RLS

No projeto: menu SQL Editor → New query → cole e rode:

create table if not exists analises_4d (
  id            bigint generated always as identity primary key,
  created_at    timestamptz default now(),
  cliente       text not null,
  periodo       text,
  momento       text,
  ct_pct        numeric,
  gmv_total     numeric,
  gmv_d1        numeric,
  gmv_d3        numeric,
  gmv_d4        numeric,
  d1_pct        numeric,
  d3_pct        numeric,
  d4_pct        numeric,
  conc_sku      numeric,
  comissoes     numeric,
  custo_amostras numeric,
  n_amostras    numeric,
  ads_spend     numeric,
  ads_gmv       numeric,
  roas          numeric,
  n_creators    numeric,
  top_creator_pct numeric,
  nota_d1       numeric,
  nota_d2       numeric,
  nota_d3       numeric,
  nota_d4       numeric,
  prioridade    text,
  fm_top_prod   numeric,
  fm_top_creator numeric,
  payload       jsonb
);

-- Liga o RLS e permite SÓ inserir pela página pública (anon).
alter table analises_4d enable row level security;

create policy "anon pode inserir" on analises_4d
  for insert to anon
  with check (true);

-- (Sem policy de SELECT para anon: ninguém lê os dados pelo navegador.
--  Você lê pelo painel do Supabase, que é autenticado.)

Passo 3 — Pegar URL e chave anon

No projeto: Project Settings → API. Copie:
- Project URL (ex.: https://xxxx.supabase.co)
- Project API keys → anon public

Passo 4 — Preencher a config

Abra entrada-config.js (nesta pasta) e preencha:

window.SUPA = {
  url: "https://xxxx.supabase.co",
  anonKey: "a-chave-anon-public",
  table: "analises_4d"
};

Suba pro hub (publicar). Pronto: o botão "Salvar no banco" da página passa a funcionar.

Como consultar depois

  • No Supabase: Table Editor → analises_4d (filtra por cliente), ou
  • SQL Editor, ex.: a última análise de cada cliente:
select distinct on (cliente) cliente, created_at, momento, ct_pct, prioridade
from analises_4d
order by cliente, created_at desc;
